P0 — correctness

Residual sign inversion in linesearch

newtonLoop defines R = F_int - F_ext. But linesearch computes R_trial = F_ext_current - F_int_trial — inverted sign. The monotonicity test R_norm_new < R_norm_old uses the same magnitude so it passes numerically, but the Armijo condition and dot-product guard in armijoSearch use the sign-dependent quantity dot(R, dU), which will fire with wrong polarity.

// newtonLoop (line 49) R = F_int - F_ext; // R = +residual // linesearch (line 15) R_trial = F_ext_current - F_int_trial; // R = -residual ← BUG // armijoSearch (line 30) depends on sign: r_try <= (1 - c1*alpha) * r0 // norms equal → passes // but dot product guard breaks snap-through detection
Fix: unify to R = F_int - lambda*F_ext everywhere. Pass the residual from the caller, do not re-assemble inside line-search utilities.
P0 — correctness

Double plastic history commit in adaptive solver

FEM_Solver_Adaptive/solveStage.m line ~95 calls solveStage → newtonLoop → commitHistory, then immediately calls obj.state.appendStep which iterates elements and calls recoverGaussPointData again. For plastic elements this double-reads HistoryData after commit, producing a plastic strain state that is one step ahead of what was actually archived. This will silently corrupt all plastic post-processing.

// solveStage.m line ~85-100 [converged, U_trial, reaction, iters] = obj.newtonLoop(...) // ↑ newtonLoop already commits HistoryData via commitHistory() // Then 10 lines later: for e = 1:nElems plasticSnap{e} = obj.Elements{e}.HistoryData; // reads COMMITTED state end obj.state.appendStep(U_converged, 0, plasticSnap, ...)
Fix: capture TrialHist BEFORE committing in newtonLoop; pass it out. commitHistory and snapshot must use the same TrialHist reference to guarantee consistency.
P0 — correctness

solveIncrementalStage local function shadow

The file solveIncrementalStage.m defines a local function assembleForArcLength at line ~39 as a closure AND redeclares a second function with the same name at the bottom of the file (lines ~290+). In MATLAB, the second definition shadows the closure in the while-loop body, meaning the stage driver calls the wrong assembler — one that uses obj.F_ext_start rather than the stage-local F_ext_total. This causes load-factor drift between stages.

// Line ~39: closure captures F_ext_total correctly function [R,KT,fext,TH] = assembleForArcLength(u,lambda,~,~) [KT_full,F_int,TH] = obj.assembleTangentSystem(u); fext = F_ext_total; // ← correct stage force ... // Line ~290: LOCAL FUNCTION SHADOW — same name, different logic function [R,KT,fext_curr,TrialHist] = assembleForArcLength(obj,u,lambda) F_ext_total = obj.F_ext_start + ...; // ← stale global force
Fix: remove the duplicate local function entirely. Rename the bottom one or move it to a private method with a distinct name.
P0 — correctness

SolutionState dependent properties bypass state object

FEM_Solver_Nonlinear exposes dependent properties (U_Hist, LambdaHist, StepCount etc.) that delegate to obj.state. But solveStage (in the Adaptive solver) still writes directly to obj.U_Hist, obj.History_Time, and increments obj.StepCount directly — bypassing the SolutionState entirely. The two systems diverge immediately; postprocessors reading Sol.state.snapshot() will see empty history.

// FEM_Solver_Adaptive/solveStage.m — direct field writes: obj.U_Hist(:, obj.StepCount) = obj.U; // bypasses state obj.History_Time(obj.StepCount) = ...; // bypasses state obj.StepCount = obj.StepCount + 1; // bypasses state // FEM_Solver_Nonlinear — dependent property reads from state: function v = get.U_Hist(obj) v = obj.state.U_Hist(:, 1:obj.state.StepCount); // sees nothing
Fix: Remove direct field access in solveStage. All history writes must go through obj.state.appendStep(). Delete the now-redundant direct obj.U_Hist property.
P0 — correctness

ConvergenceMonitor dU input is empty in arc-length corrector

In solveIncrementalStage line ~142 the corrector calls mon.check(R_f, [], u_trial(free_dofs), fext_f, i) — passing [] for dU_free. The monitor then computes norm([]) = 0 for displacement/energy norm, making those criteria always trivially satisfied. If NormType is 'energy' or 'displacement' the solver reports spurious convergence at iteration 1.

// solveIncrementalStage ~line 142 if mon.check(R_f, [], u_trial(free_dofs), fext_f, i) // ← dU = [] // ConvergenceMonitor.check: case 'energy' e_curr = abs(dU_free' * R_free); // = abs([]' * R_f) = 0 // → err = 0 / dU0_R0 = 0 → converged = true on iter 1
Fix: compute dU_free = u_trial(free_dofs) - u_prev(free_dofs) and pass it. Cache u_prev at start of each corrector iteration.
P0 — memory / crash

SolutionState grows U_Hist without trimming on rolling mode

SolutionState.growArrays pre-allocates in chunks but the rolling-mode eviction at line ~96 zeroes old columns but never shrinks the array. After 10,000 steps with RollingWindow=100 the array is still 10,000 columns wide in memory. For large models (50k DOFs) this is ~4 GB wasted. The intent of rolling mode is entirely defeated.

// SolutionState.m ~line 90 (rolling eviction) if strcmp(obj.MemoryMode, 'rolling') && s > obj.RollingWindow oldest = s - obj.RollingWindow; obj.U_Hist(:, oldest) = 0; // zeroes but does NOT shrink! // array still has s columns allocated
Fix: maintain a circular buffer of RollingWindow columns with a modular index. Alternatively, compact the array every RollingWindow steps.
P1 — robustness

arcLengthStep tangent rebuild flag never resets

In the corrector loop of solveIncrementalStage, rebuild_tangent = true is set at line ~165 when the iteration count exceeds 7 — but the subsequent continue skips the rest of the loop body including the final assembly. On the next iteration, the tangent is rebuilt but rebuild_tangent is set to false immediately after, so iterations 9+ will use a stale factorization again.

P1 — robustness

DispControlStrategy ControlDOF_local only set in predictor

ControlDOF_local is cached in predictor() but constraint() can be called before predictor() is called (e.g. in the initial residual evaluation). If called first, ControlDOF_local = 0 and the constraint indexes u_f(0), which throws an index error in MATLAB.

P1 — robustness

Armijo search modifies U_curr through F_ext alias

armijoSearch creates U_try = U_curr (a copy) then calls assembleinternalforceONLY(U_try). If element objects have any side effects in their force computation (which plastic elements do via HistoryData probe paths), this mutates committed state during the search. The search is not side-effect-free.

P1 — data integrity

FEM_DataManager listener holds hard reference to Sol

attachToSolver creates a listener closure capturing Sol by reference. If the solver is cleared or replaced in a restart scenario while listeners are still live, the closure keeps the old solver object alive in memory (MATLAB handle class semantics), preventing GC and potentially writing stale data to the project.

P1 — correctness

recoverAllGaussPoints uses live Elements after restart

When stepIdx is not the current step, recoverAllGaussPoints swaps in archived HistoryData, calls recoverGaussPointData, then swaps the live state back. But this is not thread-safe and relies on savedHD = elObj.HistoryData being a value copy — which it is for structs. However if the archive is missing for any element, it silently falls back to live state, producing a mixed-step result with no warning.

Hardening plan

Wave 1 — correctness (1 week)

1

Fix residual sign convention

Standardize R = F_int - lambda·F_ext in every file. Audit: newtonLoop, linesearch, armijoSearch, solveIncrementalStage closure, arcLengthStep. Add a unit test: assert norm(R_newton + R_linesearch) < tol.

2

Remove assembleForArcLength function shadow

Delete the bottom local function in solveIncrementalStage.m. Rename the closure to assembleFn to avoid any future shadowing. Verify the stage-local F_ext_total is used throughout.

3

Unify history writes through SolutionState

Delete obj.U_Hist, obj.History_Time as stored properties; keep only as dependent. Remove all direct field writes in solveStage. Pipe solveStage through state.appendStep().

4

Fix double plastic commit

In newtonLoop, return TrialHist to the caller and do NOT call commitHistory internally. Let solveStage / solveIncrementalStage commit exactly once per converged step, then snapshot the pre-commit TrialHist for archival.

5

Pass dU_free to ConvergenceMonitor

In the corrector body, maintain u_prev = u_trial before each update. Compute dU_free = u_trial(free_dofs) - u_prev(free_dofs) and pass to mon.check(). This enables energy and displacement norm paths.

6

Fix SolutionState rolling mode circular buffer

Replace grow-and-zero with a fixed [nDofs × RollingWindow] preallocated ring. Write pointer = mod(StepCount-1, RollingWindow) + 1. Expose a getU(globalStep) that maps global step index to ring position.

Wave 2 — data manager (1 week)

7

Replace O(N) MAT append with matfile() streaming

Use MATLAB's matfile() with Writable=true to append columns to U_hist and lambda_hist without loading the full file. For GP history, write one variable per step (gp_NNNNN) to avoid the struct-load-modify-save cycle.

8

Decouple DataManager listener from Sol reference

Change onStepConverged_ to receive only SolverEventData (already contains U, lambda, iters). Move the plastic GP snapshot capture into the solver's notify() call — pack it into the event data. The listener then only writes; it never reads the solver.

9

Enforce snapshot-only postprocessor access

Change FEM_Postprocessor_v2 constructor to accept SolutionSnapshot instead of a live solver handle. This enforces the immutability boundary and prevents silent live-state reads during historical step queries.

10

Add missing-archive explicit error in recoverAllGaussPoints

Replace the silent fallback to live state with an explicit warning or error when the archive is missing for a requested historical step. Provide a useCurrentState option flag for the caller to opt in to live-state fallback explicitly.

Wave 3 — decomposition & governance (2 weeks)

11

Extract correctorLoop from solveIncrementalStage

Target: 8 responsibilities → 5 private methods. The corrector Newton body (lines ~100–200) becomes correctorLoop(u0, l0, strategy, ds, assembleFn, free_dofs) returning [u, l, F_int, TrialHist, converged, iters]. No obj mutation inside the loop — pure function semantics.

12

Remove deprecated solver subclasses

Delete FEM_Solver_ArcLength and FEM_Solver_Adaptive after migration metrics (no usages in tests/examples). The warning + delegate pattern is correct but creates dead code surface.

13

Nonlinear replay determinism test

Add a test that runs a 10-step snap-through, serializes SolutionSnapshot, reloads, re-runs post-processing, and asserts identical stress fields. This guards the commit/snapshot/archive pipeline end-to-end.
